PROJECT OVERVIEW
----------------
Print X is a full-stack 3D printing e-commerce platform with customer-facing 
store and admin management panel. Built with Django REST Framework backend 
and vanilla JavaScript frontend.

================================================================================
                        FOLDER STRUCTURE
================================================================================

/backend/
---------
PURPOSE: Django backend server handling all API requests, database operations,
         authentication, and business logic.

  /api/
  -----
  PURPOSE: Main Django app containing models, views, serializers, and API endpoints.
  
    models.py
    ---------
    LOGIC: Defines database schema using Django ORM
    - Product: Store products with name, price, description, image, stock
    - Cart: User shopping cart items with quantity
    - Order: Customer orders with tracking ID, status, items snapshot, delivery date
    - Payment: Payment records linked to orders (GCash, Maya, Bank Transfer)
    - CustomRequest: Custom 3D print requests with STL file uploads
    - UserProfile: Extended user data (phone, address, profile picture)
    - ProductReview: Product ratings and comments (1-5 stars)
    - Category: Product categorization
    
    views.py
    --------
    LOGIC: Main API endpoints using DRF decorators
    - Authentication: register(), login_view(), logout_view() with JWT tokens
    - Products: CRUD operations for products (public read, admin write)
    - Cart: Add/update/remove items, calculate totals
    - Orders: Checkout, view orders, track by ID
    - Custom Requests: Submit STL files, upload, cancel
    - Admin: Dashboard stats, manage orders/products/users
    - Reviews: Get product reviews, add/edit/delete reviews
    - Email: Send HTML emails for order status, custom approvals, cancellations
    
    new_features_views.py
    ---------------------
    LOGIC: Additional feature endpoints
    - Order tracking by tracking_id (public, no auth)
    - Order cancellation requests with approval workflow
    - User profile management (view, update, change password)
    - Revenue chart data for admin dashboard
    - Phone number validation
    
    urls.py
    -------
    LOGIC: URL routing mapping endpoints to view functions
    - /api/register/, /api/login/, /api/logout/
    - /api/products/, /api/products/<id>/
    - /api/cart/, /api/cart/add/, /api/cart/update/<id>/
    - /api/checkout/, /api/orders/
    - /api/custom/, /api/custom/<id>/upload/
    - /api/admin/stats/, /api/admin/orders/, /api/admin/custom/
    - /api/products/<id>/reviews/, /api/reviews/<id>/delete/
    - /api/track/<tracking_id>/
    
    email_utils.py
    --------------
    LOGIC: Async email sending using threading
    - send_email_async(): Sends emails in background thread to prevent blocking
    - Prevents HTTP request delays when sending emails
    
    admin.py
    --------
    LOGIC: Django admin panel configuration
    - Registers models for admin interface

================================================================================
                        KEY TECHNICAL CONCEPTS
================================================================================

AUTHENTICATION FLOW
-------------------
1. User submits login credentials
2. Backend validates and returns JWT access + refresh tokens
3. Frontend stores tokens in localStorage
4. All API requests include: Authorization: Bearer <access_token>
5. On 401 error, frontend uses refresh token to get new access token
6. If refresh fails, user is logged out

CART SELECTION SYSTEM
----------------------
1. Cart page displays checkboxes for each item
2. JavaScript Sets track selected items (selectedItems, selectedCustomItems)
3. "Select All" toggles all checkboxes
4. Dynamic summary calculates total for selected items only
5. On checkout click, selected IDs stored in sessionStorage
6. Checkout page reads sessionStorage and filters items

ORDER TRACKING SYSTEM
----------------------
1. Order created → generate_tracking_id() creates 16-char hex ID
2. Tracking ID stored in Order.tracking_id field (unique)
3. Public endpoint /api/track/<tracking_id>/ (no auth required)
4. Case-insensitive lookup
5. Returns order status and details

EMAIL NOTIFICATION SYSTEM
--------------------------
1. Admin updates order status → _send_status_email() called
2. Email sent asynchronously via threading (email_utils.py)
3. HTML email templates with order details
4. Gmail SMTP with app password from environment variables
5. Falls back to console backend if credentials not set

REVIEW SYSTEM
-------------
1. ProductReview model with unique constraint (user + product)
2. One review per user per product
3. Update existing review if user reviews again
4. Average rating calculated on-the-fly
5. Admin and review owner can delete reviews

RESPONSIVE DESIGN
-----------------
1. Mobile-first approach
2. CSS clamp() for fluid typography: clamp(min, preferred, max)
3. Grid auto-fit: repeat(auto-fit, minmax(min, 1fr))
4. Breakpoints: 480px, 700px, 860px, 900px, 1200px
5. rem units for zoom accessibility
6. Minimum touch targets: 2.5rem (40px)

ADMIN PANEL ARCHITECTURE
-------------------------
1. Single-page application (no page reloads)
2. Panel switching via showPanel() function
3. Separate localStorage keys (px_admin_*)
4. Sidebar + horizontal scroll nav (synced)
5. Mobile: sidebar becomes overlay
6. Each panel loads data on activation

CUSTOM REQUEST WORKFLOW
------------------------
1. Customer submits STL file + specs → status: pending
2. Admin reviews → status: reviewing
3. Admin sets price → status: approved (email sent)
4. Approved request appears in customer cart
5. Customer checks out → status: completed
6. Admin can cancel with reason (email sent)

DELIVERY DATE SYSTEM
--------------------
1. Admin changes order to "processing" or "shipped"
2. Modal appears requiring delivery date input
3. Date validated (must be future date)
4. Date stored in Order.estimated_delivery_date
5. Displayed on public tracking page
6. Included in status update email

                        DATABASE SCHEMA

User (Django built-in)

Product
- id, name, price, description, image, stock, category_id, created_at

Payment
- id, order_id, method, amount, status, reference_number, created_at

CustomRequest
- id, user_id, file_name, file_size, stl_file, material, color, quantity

UserProfile
- id, user_id (unique), phone, address, profile_picture, created_at, updated_at

ProductReview
- id, product_id, user_id, rating (1-5), comment, created_at, updated_at
- UNIQUE(product_id, user_id)

Category
- id, name (unique), description, created_at

================================================================================
                        RUNNING THE PROJECT
================================================================================

1. Install Python dependencies:
   cd backend
   pip install -r requirements.txt

2. Run migrations:
   python manage.py migrate

3. Create superuser (admin):
   python manage.py createsuperuser

4. Start server with email config:
   start_server.bat
   
   OR manually:
   set EMAIL_HOST_USER=3dprintxcontact@gmail.com
   set EMAIL_HOST_PASSWORD=mugptymalyopurwb
   python manage.py runserver

5. Open frontend:
   - Customer: http://127.0.0.1:8000/docs/customer/index.html
   - Admin: http://127.0.0.1:8000/docs/admin/admin.html

================================================================================
                        SECURITY FEATURES
================================================================================

1. JWT Authentication: Secure token-based auth with refresh mechanism
2. Password Hashing: Django's PBKDF2 algorithm
3. CSRF Protection: Disabled for API (using JWT instead)
4. SQL Injection: Protected by Django ORM
5. XSS Protection: HTML escaping in templates
6. Rate Limiting: 10 login attempts per minute per IP
7. Admin Access: Requires is_superuser flag
8. File Upload: Validates .stl extension
9. Email Validation: Unique email constraint
10. Phone Validation: Format checking (09XXXXXXXXX or +639XXXXXXXXX)

================================================================================
                        TROUBLESHOOTING
================================================================================

ISSUE: "Failed to load reviews"
FIX: Ensure ProductReview model exists and migrations are applied
     python manage.py makemigrations
     python manage.py migrate

ISSUE: Emails not sending
FIX: Check EMAIL_HOST_USER and EMAIL_HOST_PASSWORD are set
     Use start_server.bat or set manually before running server

ISSUE: 401 Unauthorized errors
FIX: Check JWT tokens in localStorage
     Clear localStorage and login again

ISSUE: CORS errors
FIX: Ensure CORS_ALLOWED_ORIGINS in settings.py includes frontend URL

ISSUE: Admin login fails
FIX: Create superuser: python manage.py createsuperuser
     Ensure is_superuser=True in database

ISSUE: File upload fails
FIX: Check MEDIA_ROOT and MEDIA_URL in settings.py
     Ensure /media/stl_files/ directory exists
